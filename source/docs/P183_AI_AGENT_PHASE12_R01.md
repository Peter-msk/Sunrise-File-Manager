# Sunrise File Manager v1.8.3 — AI Phase 1·2 개발 인수인계 R01

## 변경 범위

- `AiNaturalLanguageService`: 한국어 자연어 명령을 **제한된 오프라인 문법**으로 해석. LLM 아님. 지원하지 않는 표현은 추측하지 않고 오류 처리.
- `AiAgentOrchestrator`: 선택/현재 폴더의 파일 탐색 → 조건 필터링 → 파일 스냅샷 → 기존 `AiPlanService.Validate` 계획 검증.
- `AiCommandPanel`: 자연어 입력, 검색 범위 지정, 검색 결과 확인, 실행 전 계획 표 및 별도 승인.
- `ExplorerPane.RevealFileAsync`: 검색 결과를 더블클릭해 일반 탐색기에서 해당 파일을 선택.
- 기존 `FileActionsService`, `TransferService`, `FileMemoStore`, `AiJournalStore` 재사용. 신규 임의 셸 실행 없음.

## 사용자에게 명시할 기능·한계

1. 로컬 지원: 파일명에 특정 문자열 포함, 한 가지 확장자, 파일 유형(문서·이미지·동영상), 최근 N일 수정, 확장자/유형/수정일/연도/크기 기준 분류와 복사·이동 계획.
2. 검색 범위: 기본값은 **명시적으로 선택한 항목**. 사용자가 선택해야만 **현재 폴더와 하위 폴더** 검색. 최대 5,000항목 검사, 검색 결과 1,000개, 탐색 깊이 12단계. 초과하면 실패로 표시하며 조용히 일부만 반환하지 않음.
3. `#memo`, `.sunmemo` 및 링크 경로는 발견 검색에서 제외. 메모의 이동은 기존 `FileActionsService.MoveEntry` 경유.
4. 지원하지 않는 기능: 내용 의미 검색·중복 판정·최종본 판정, 복수 확장자 검색, 외부 AI의 자율적 파일 탐색, 영구 삭제 및 무승인 변경.
5. 검색 명령은 읽기 전용. 파일 복사/이동은 무조건 변경 전후 미리보기, 충돌 검사, 기존 승인 및 작업 기록 경유.
6. Google Gemini 사용은 **별도** 기존 고급 명령용 HTTPS 프록시/동의 기능이며, 자연어 검색은 전송하지 않음. Peter 실제 연결 없음.
7. 내부 AI는 웹 브라우저 확장을 자동 조작하지 않음. 현재 파일 시스템에서 동작하는 명시적 기능을 구현함.
8. 여러 경로에서 발견한 동일 파일명을 복사할 때 충돌 정책은 **건너뛰기** 또는 **번호 추가**. 이동은 기존 엔진의 동일 볼륨 제약 유지.

## Windows 검증 필요 사항

`BUILD_ON_WINDOWS.cmd`에서 .NET 10 x64 SDK로 C# LogicTests(새 `AiNaturalLanguageTests` 포함) → WPF Publish → Portable 패키징. 새 버전이므로 과거 PASS 결과는 사용하지 않음. 예상 실제 Windows EXE와 GUI 캡처는 이 Linux 환경에서 만들 수 없음.

실기 검사: ① 파일명 조건과 확장자 ② 선택항목 및 하위 폴더 범위 ③ #memo 제외 ④ 검색 결과 더블클릭 ⑤ 복사·이동 계획 사전 승인 ⑥ 파일 이동 후 기존 메모 연결 ⑦ 충돌·취소·타 드라이브 이동 차단 ⑧ 2~4분할과 우측 독립 미리보기 영역 및 DPI.
