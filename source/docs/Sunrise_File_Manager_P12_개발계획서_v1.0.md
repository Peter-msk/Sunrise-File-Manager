## 1. 목표와 제품 포지셔닝

Sunrise File Manager의 주 기능은 Windows 파일 탐색과 안전한 파일 조작이다. 기본 1개 탐색기를 제공하고, 필요한 경우에만 Q-Dir처럼 2·3·4분할을 사용한다. 웹 브라우저를 파일 관리자 안에 내장하는 기능은 업무 효율 기여도가 낮다고 판단해 신규 개발 우선순위에서 제외한다. 대신 사용자가 자연어로 파일명 일괄 변경, 폴더 생성, 분류, 복사·이동, 휴지통 정리를 요청하는 **AI 파일 작업 보조 기능**을 도입한다.

**P12 완료의 정확한 의미:** 기존 파일 탐색기와 문서 미리보기를 유지하면서 *AI 명령 → 구조화된 실행 계획 → 로컬 검증 → 변경 전 미리보기 → 사용자의 실행 승인 → 기존 파일 서비스 실행*의 기본 수직 경로를 구축한다. P12의 최소 완료 범위는 **비파괴적 파일명 변경 계획과 폴더 생성**이며, 일괄 복사·이동·삭제 자동화는 후속 게이트 통과 후 차례로 연다.

### 필수 유지 계약

1. **단일 탐색기 기본**. 필요할 때만 2~4분할. 탐색 경로/탭/트리/주소/검색/정렬/큰 아이콘 보기/우클릭/Windows 속성 유지.
2. **단일 파일의 한 페이지 미리보기** 유지. PDF는 WinRT 렌더 경로 + 텍스트 대체모드, HWPX/DOCX는 기존 텍스트 미리보기(원본 페이지 재현 기능으로 과장하지 않음).
3. 기존 `FileActionsService` 및 `TransferService`를 실행 계층의 단일 기준원으로 재사용. 별도의 무검증 파일 수정 엔진을 만들지 않음.
4. 기존 Windows 권한과 SecureDisk의 읽기·저장·반출 정책을 **변경·우회하지 않음**. 승인 없는 외부 전송, 브라우저 프로세스 위장, 금지 파일 우회 복사 금지.
5. AI 기능 장애, 네트워크 불통, API 결제/한도 초과 시에도 **일반 탐색기·파일 미리보기·수동 파일 작업은 정상 작동**해야 함.
6. 승인 전에는 원본 파일에 어떠한 변경도 발생하지 않아야 하며, 승인 후에도 범위 밖 파일 변경은 금지한다.

## 3. 최종 목표 아키텍처

```text
Windows 탐색기 UI (WPF)
  ├─ 활성 탐색기/선택 항목 스냅샷
  ├─ AI 명령 패널 (접기/펼치기, 기본 닫힘)
  │     ├─ 사용자 명령
  │     ├─ 로컬 규칙 처리 (명확한 일괄 처리: AI 불필요)
  │     ├─ Gemini 명령 해석 어댑터 (선택적, 서버측 비밀 관리)
  │     └─ 구조화된 실행 계획(JSON, **데이터일 뿐 실행 명령이 아님**)
  ├─ 계획 검증기 (범위/파일명/충돌/쓰기권한/재분석)
  ├─ 변경 전후 미리보기 + 명시적 사용자 승인
  ├─ 단일 작업 큐 / 작업 진행률 / 취소 / 결과 기록
  └─ 기존 FileActionsService 및 TransferService
```

AI는 **파일 시스템을 직접 조작하지 않고 계획만 제안**한다. 프로그램은 모델 응답을 불신 입력으로 취급하며, 허용된 동작으로만 변환한다. `powershell`, `cmd`, 임의 실행파일, 임의 URL 호출, 동적 코드, 확장 가능한 명령 셸을 계획 형식에 포함하지 않는다.

### 계획 스키마 초안(예시이며 현재 코드가 아님)

```json
{
  "schema_version": 1,
  "scope_id": "locally-issued-snapshot-id",
  "operations": [
    {
      "operation": "rename",
      "entry_id": "opaque-entry-id",
      "new_name": "2026_사업계획서.pdf"
    }
  ],
  "requires_confirmation": true
}
```

- 서버로 전달되는 `entry_id`는 **임시 로컬 식별자**이고 절대 경로나 접근 토큰을 포함하지 않는다.
- 허용 `operation`은 단계별 화이트리스트를 사용한다: P12 `rename`, `mkdir`; P13 `copy`, `move`; P14 이후 제한된 `recycle`.
- `scope_id`는 실행 계획 생성 시점의 폴더 스냅샷을 참조한다. 범위가 바뀌면 재계획/재승인 필요.
- 실행 직전 원본 존재/형식/변경 시각(필요 시 파일 ID·해시)/경로 실체화/경로 이동 여부를 재검사한다. 재분석 결과가 기존 미리보기와 다르면 정지한다.
- 출력 스키마의 유효성을 통과해도 **의미 검증은 별도** 수행한다. Gemini의 Function Calling/구조화 출력은 실제 OS 명령 권한을 뜻하지 않는다.

## 4. UI/UX 세부 계약

- **메인 기본 화면**: Windows 탐색기형 좌측 트리, 중앙 넓은 파일 목록, 우측 상세 정보. AI는 `AI 정리` 버튼 또는 단축키로 여는 별도의 오른쪽 패널. AI 패널 닫으면 파일 목록 폭 복원.
- **AI의 기본 작업 범위**: 현재 활성 탐색기의 명시적으로 선택된 항목. 선택이 없다면 대상 폴더를 화면에 명시하고 별도 동의를 받아야 한다. **전체 PC/전체 드라이브 암묵적 선택 금지**.
- **명령 결과**: `요청 해석`, `대상 X개`, `예상 작업`, `변경 전 → 변경 후`, `건너뜀/충돌`, `외부 전송 정보`를 표시.
- **버튼**: `계획 다시 만들기`, `대상 수정`, `실행 승인`, `취소`. 실행 버튼은 계획 검증 성공 이전 비활성화.
- **오류**: 어떤 파일이 어떤 이유로 실패했는지 항목별 표시. 전체 진행률·현재 파일·완료/실패/건너뜀 개수 표시. 작업 완료·부분 실패·취소를 명확히 구분.
- **접근성**: 키보드 포커스, Tab 순서, 100/125/150% DPI, 작은 화면에서도 파일 목록이 0폭으로 줄지 않는 레이아웃.

## 5. 개발 단계별 작업 명세와 완료 기준

### P12 — Gemini 계획 생성 및 AI 패널 전환 (v1.2.0)

1. 원본 P11 소스 SHA 확인, 브랜치/백업 생성, Windows 실기 빌드 결과 확보(가능할 경우 우선 실행).
2. 기존 파일 관리자와 미리보기 기능의 회귀 스냅샷 작성.
3. `ChromePane`의 사용 UI를 AI 패널로 전환. Chromium 의존성은 참조 제거/세션 마이그레이션/빌드 확인을 순서대로 진행하고, CEF 관련 캐시를 사용자 허락 없이 삭제하지 않음.
4. AI 패널 컴포넌트, 활성 항목 스냅샷과 로컬 규칙 엔진을 구현. 네트워크 연결이 없어도 `접두어 추가`, `일련번호 부여`, `폴더 생성` 등의 명확한 명령 계획 가능.
5. Gemini 어댑터는 **응답 스키마 검증 후 로컬 계획 변환까지만** 연결. 불명확한 요구는 사용자에게 범위나 규칙 선택을 요청.
6. 계획 미리보기 후 명시적 승인으로 `rename`과 `mkdir`만 수행. 삭제·이동·복사는 P12 AI 명령 실행 목록에서 비활성화.
7. 단일 작업 실행 상태/취소/부분 실패/감사 기록 추가. 기존 로컬 기능 유지.
8. 테스트: 정상/잘못된/악의적 JSON, 허용되지 않은 명령, 경로 탈출, 파일명 충돌, 권한 없음, 파일 변경 중 재승인, 네트워크 오류.

**P12 종료 게이트**: 테스트용 30개 파일 이름 변경 계획/미리보기/승인/실행이 정확하고, 승인 전 변경이 0건, 실패 항목이 투명하게 기록되며, 기존 1~4분할 및 미리보기 회귀가 성공. Windows `BUILD_WINDOWS.ps1` 결과 및 CEF 제거 후 게시 점검을 보고서로 제출.

- **완료 게이트**: 테스트 1,000개 파일 작업에서 복사·이동 결과 수와 파일 내용 해시 검증, 실패 후 원본 보존.

### P14 — 변경 기록 및 복구 계약 (v1.4.0)

- 작업별 불변 계획 ID, 사용자 승인 시각, 범위, 실행 전후 경로, 오류·완료 상태 저장.
- 실행 취소는 검증 가능한 이름 변경/동일 볼륨 이동 등 제한된 범위에 우선 적용. 중간에 파일이 변경되면 자동 복구하지 않고 사용자 확인.

- 반복 클릭·비정상 종료·재시도에 대한 중복 실행 방지 및 저널 복구 계약.
- **완료 게이트**: 취소·부분 실패·중단 복원에서 원본 손상/비의도 삭제 0건.

### P15 — 지능형 정리 기능 (v1.5.0)

- SHA-256 중심의 로컬 중복 탐지, 확장자/수정일/메타데이터 기반 분류.
- 문서 내용 기반 분류는 **명시적 동의와 보안 등급 확인 후**, 최소 정보만 전송. 업무용 보안 문서는 외부 API 전송 기본 금지.
- 사용자별 대용량 작업 상한, 예상 호출량/비용 표기, 오프라인 동작 유지.
- **완료 게이트**: 오탐/중복 탐지 보고, 민감 자료의 비승인 전송 0건.

### P16 — UI·성능·배포 안정화 (v1.6.0)

- 좁은 패널/고DPI/대량 파일/로딩·진행률 검증 및 UI 레이아웃 마감.
- Windows 설치·게시 형태 최적화, 제거된 Chromium 의존성/네이티브 파일 잔존 여부 검사.
- 실제 Windows 빌드, 코어 회귀, E2E 수용시험, 배포 매니페스트/해시/인수 문서 확정.

## 6. Gemini 연동 보안/운영 원칙

1. **Chrome의 Gemini UI를 임베드하지 않는다.** Gemini API의 구조화 응답 또는 Function Calling을 활용한 독립 어댑터로 구현한다.
2. **API 키**: 소스·설정 JSON·로그·클라이언트 바이너리에 하드코딩하지 않는다. 공유·배포 프로그램은 서버측 프록시와 서버 비밀 저장소를 원칙으로 한다. 사용자 개인 실험과 다중 사용자 배포의 인증·운영 모델을 구분한다.
3. **송신 기본값**: 파일명, 상대 경로, 문서 내용, 사용자 식별자까지 모두 외부 유출 가능 정보이다. 기본은 로컬 규칙 처리. Gemini 전송은 사용자에게 전송 항목을 먼저 보여주고 동의를 받을 때만 허용. 보호 자료는 별도 승인 없는 전송 불허.
4. 프롬프트 주입 방어: 파일명·문서 내용에 있는 문장은 작업 명령이 아니라 자료로 취급. 모델 결과가 삭제, 셸 실행, API 키 제출 등을 요청해도 로컬 화이트리스트와 사용자 승인 없이는 실행 금지.
5. 보안 경로: `SecureDisk`, 문서중앙화 및 기타 접근 제한 구역의 접근 권한 상승, 우회 복사, 외부 업로드를 통한 반출, 정책 무력화 기능 금지.
6. **비용**: 호출 타임아웃/재시도 상한, 모델 ID 및 전송량 기록, 비용/한도 오류 안내. 모델 버전은 개발 시 공식 지원 상태를 확인하고 고정·관리.
7. 감사 로그는 기본적으로 원문 내용/기밀 파일명을 담지 않고 작업 ID/결과/오류 코드 중심으로 저장하며 보존 기간·사용자 삭제 기능을 운영 정책에 맞춰 설정.

## 7. 기술·테스트/릴리스 게이트

- **빌드 대상**: Windows 10/11 x64, .NET 10 SDK, WPF. P11 PDF WinRT 타깃의 실제 컴파일 호환성 선확인.
- **정적검사**: 변경 범위와 관련된 파서·이벤트·권한·스키마 계약만 실행. 이전 PASS 전부를 Windows 빌드 시 재실행하지 않음.
- **실행검증**: `.NET LogicTests` + WPF 게시(각 1회), 최소 1개 실제 PC에서 파일 조작/UI/권한 오류 시험.
- **필수 반례**: 충돌·잘못된 이름·재분석 시점 변경·읽기 전용·NTFS 접근 거부·경로 재해석(심볼릭 링크/접합점)·중복 작업·네트워크 실패·사용자 취소.
- **테스트 데이터**: 실데이터가 아닌 임시 샌드박스 폴더. 해시와 파일 개수 비교로 불변성 검증.
- **출력물**: 전체 소스 ZIP, 변경 내역, `WINDOWS_BUILD_RESULT.json`, 오류 로그, 변경 범위별 회귀 결과, 운영 제한 사항, 후속 인수 문서.
- **검증 용어**: 정적 검사 PASS ≠ Windows 컴파일 PASS ≠ 실기 기능 PASS. 미실행은 반드시 NOT_RUN 표기.

## 8. 우선 결정할 사항 및 기본 가정

- **기본 UI**: AI 패널은 필요할 때만 표시(채택).
- **P12 첫 실행 기능**: 이름 변경·새 폴더 생성, 승인 후 실행(채택).
- **Gemini 인증**: 제품 배포를 고려해 서버측 프록시 설계를 우선하되, 실제 백엔드 운영 여부/비용 계정 제공은 개발 시 결정. 키가 없어도 오프라인 명령 기능이 작동해야 함.
- **보호 파일**: 소유권/승인 범위를 확인할 수 없다면 Gemini 업로드·변경 시도 불허(기본값).
- **브라우저**: 기존 CEF는 P11 기준본에만 보존하고, P12 주 UI에서 제거. 제거 중 빌드 실패 시 원복 가능한 스냅샷 유지.
