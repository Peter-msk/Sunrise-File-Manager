# Sunrise File Manager R12 — 최종 UI/소스 감사 보고서

## 1. 검토 기준과 방법

- 기준본: `Sunrise_File_Manager_COMPANY_FULL_SOURCE_R11_UI_TEXT_SCROLL_FIX.zip`의 실제 C#·WPF XAML 전체 소스.
- 정적 코드 감사: C# 이벤트 연결, XAML 문법 및 화면 구조, 세션 저장 정책, 회사 OneFile 빌드 스크립트의 배포 설정, AI 및 파일 메모 기능의 소스 위치 검토.
- HTML 실험: `Sunrise_File_Manager_R12_UI_Prototype.html`. R11 XAML 레이아웃·색상 팔레트를 참고하여 수작업 재구성한 **독립 UI 시뮬레이터**. XAML을 자동 변환한 결과물이 아니며 Windows WPF 화면과 1:1 동일하다고 보증하지 않음.
- HTML의 파일명과 날짜는 테스트용 가상 자료이며 실제 사용자의 파일이나 문서는 열지 않음.
- Windows WPF 빌드/실행: 이 환경에 Windows와 .NET SDK가 없어 미실행. 따라서 아래 PASS는 Windows 실행 PASS가 아님.

## 3. 실제 HTML 브라우저 검증

- Playwright + Chromium 헤드리스로 1440×900 라이트/다크, 4분할, 우측 독립 패널과 AI 동시 열기 시나리오를 캡처함.
- 브라우저 상호작용 17개 항목 PASS: 패널 기본 숨김, 단일 표시, 다크 기본 표시, 트리 휠, 설정 메뉴, 테마 변경, 4분할, 분할별 트리 숨김, AI 열고 닫기, 상세정보/미리보기 독립 표시, 표 헤더 너비 드래그, 1024/1200/1440/1920px 외부 수평 넘침 방지, JS 오류 없음.
- HTML에서 4분할+독립 미리보기+상세정보/메모+AI를 동시에 켠 경우 **파일 목록 세로 공간과 가로 폭이 매우 부족함을 재확인**. 모든 우측 패널을 자동으로 닫으면 사용자의 표시 설정을 어기므로, 각 패널의 독립 개폐·너비 조절과 명령 표시줄 적응형 축약을 사용하도록 함. 실제 Windows UI에서는 그 조합을 추가 검증할 것.
- HTML에서 `hidden` 요소를 CSS의 `display:flex`가 덮어쓰던 문제는 `[hidden]{display:none!important}`로 바로잡았음. 이 문제는 HTML 시뮬레이터에만 있던 문제로 WPF 변경 사항과 혼동하면 안 됨.

## 5. R12 실제 소스 수정 파일

1. `source/Sunrise.FileManager/Controls/ExplorerPane.xaml`: 보기 메뉴 하위 '표시 방식' 5개, '파일 유형 필터' 8개를 추가해 좁은 창에서도 명령 접근 가능하도록 변경.
2. `source/Sunrise.FileManager/Controls/ExplorerPane.xaml.cs`: `ApplyCompactCommandBar`/`ViewModeMenu_Click`/`CategoryMenu_Click` 추가, 기존 창 크기 변경 경로에 연결.
3. `source/Sunrise.FileManager/Sunrise.FileManager.csproj`: File Manager 소스 저장소로 부정확한 Ollama `RepositoryUrl` 선언 제거. Ollama 연동 코드와는 무관.
4. `ui-audit/`: 독립 HTML UI 모형, 브라우저 시나리오/렌더링 자료, 본 감사 보고서 추가.

C#의 파일 복사·삭제·이동, 사용자 세션, 메모 파일 형식, Ollama 연동, 회사 문서 접근 제한 빌드 스크립트는 수정하지 않음.

## 6. 검증과 잔여 위험

- Python 기반 기존 `unittest discover` 59/59 PASS.
- 전체 WPF XAML 13개 XML 파싱 PASS, 선언한 이벤트 230개 모두 대응 C# 메서드 문자열 존재 확인. 이는 컴파일러 검사보다 약한 검사임.
- HTML 실동작 시나리오 17/17 PASS.
- Windows 전용 C# 컴파일, WPF Visual Tree, DPI 125/150%, 실제 키보드 포커스/선택 색상, FileGrid 열 조절 및 회사 보안 프로그램에서의 OneFile 실행은 **미검증**.
- 회사 SecureDisk 정책으로 금지된 업무 문서 열람·본문 검사·Fixture 검사는 이번 감사에서 수행하지 않았음.

## 7. 다음 Windows 실기 확인 순서

1. R12 회사 전용 ZIP을 기존 버전과 구분된 새 폴더에 압축 해제, `BUILD_ON_WINDOWS_COMPANY.cmd` 실행.
2. 1분할/2분할/4분할에서 폭이 좁아질 때 명령 버튼이 축소되고 `보기 → 표시 방식/파일 유형 필터`가 정상 반영되는지 확인.
3. 다크모드 메뉴 펼침/선택, 표 헤더 드래그, 탐색트리 휠 스크롤 확인.
4. AI·미리보기·메모를 개별 표시/숨김한 뒤 재실행 시 저장 설정 복원 확인.
5. 오류 발생 시 `build-logs`와 화면 캡처만 수집. 회사 보안 문서를 추가로 읽는 검사는 수행하지 않음.
