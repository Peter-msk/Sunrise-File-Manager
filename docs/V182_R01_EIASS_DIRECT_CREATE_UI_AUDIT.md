# Sunrise File Manager v1.8.2 R01 — EIASS 실제 생성 활성화 및 화면 공간 재설계

## 자료와 문제 원인
- 실제 사용자 캡처 두 장을 비교 검토(2026-11-15). 이전 1차 창 1190×865는 사업명·용역명 입력이 창의 오른쪽 절반에 몰리고, 숨겨진 두 ID 입력 칼럼이 왼쪽 빈 공간을 차지했다.
- 상단의 `운영 쓰기 잠금 · 자동 생성 비활성`, 하단의 `생성 기능 없음`, `생성 버튼 없음` 표기는 이미 별도 운영용 작성기가 있던 코드와 모순됐다.
- 2차 팝업은 사업 폴더명 재입력 → 검토 확인 → 실행 직전 재점검 → 별도 생성 버튼 → 최종 승인 순으로 반복 확인을 요구했다. 사용자 예시(48개 생성 예상)에서도 생성 버튼은 이 완료되지 않은 절차 때문에 비활성화됐다.
- 5열 진단 표는 절대경로와 상대경로의 중복 정보로 실제 주석을 읽기 어렵고, 처리 버튼이 두 행에 흩어져 있었다.

## R01 수정한 업무 흐름
1. 메인 창에서 사업명·용역명·평가 유형 입력, `폴더 목록 계산` 버튼 클릭. 기본안 폴더 계획과 생성 근거가 표시됨.
2. 기존 기준 폴더를 선택. `누락 폴더 생성` 버튼이 활성화됨. **추가 2차 검토창·사업명 재입력·사용자 재점검 버튼 없음**.
3. 버튼 클릭 후 백그라운드에서 경로 전체 읽기·충돌 감시·엄격한 계획 지문 비교·독립 재점검. 충돌 시 생성하지 않고 경로 진단 결과 표시.
4. 누락 폴더가 있으면 **최종 Yes/No 확인 한 번**. 승인 시 `EiaWorkspaceProductionWriter.ExecuteReviewed`를 실행(로컬 NTFS/ReFS, PINNED 핸들, 단일 하위폴더만 생성). 기존 파일·기존 폴더 삭제/이동/이름변경/덮어쓰기 없음.
5. 진행률·중지·부분실패 항목·결과폴더 열기 하나의 화면에서 처리. 생성 중 창 닫기 시 중지 요청 뒤 완료/부분 결과 확인.

## 레이아웃 재구성
- 주 창 1120×780, 최소 850×610; 과도한 비율 할당을 해제해 입력영역은 최대 높이 335이고 폴더 목록이 남는 공간을 사용.
- 사업명과 용역명은 **좌측 105px 라벨 + 남는 전폭 입력칸**으로 정렬, 숨긴 ID 칼럼에 의한 오른쪽 몰림 제거.
- 저장 위치와 선택 버튼 한 줄, 오른쪽에 유일한 핵심 명령 `누락 폴더 생성` + 상태 명령 `중지`, `결과 폴더 열기` 집중.
- 경로 진단은 범위·상태·상대경로·상태설명 **4열**로 축소. 절대경로는 상대경로 셀 툴팁으로 보존. 계획표/진단표 열 크기 재배열 금지.
- 필수 기본 기능 외 복합 계약·회사/발주처 초안은 기존 접힌 상세 영역에 유지. 회사 초안은 운영용 폴더 생성에 사용하지 않음.

## 안전·검증 경계
- 생성 전에 일치한 기본안·상태 지문과 명시 승인, 폴더별 실경로 재확인을 요구.
- 기존 `EiaWorkspaceCreationEngine.ProductionWritesEnabled=false`는 읽기 전용 미리보기의 역할 격리 상태이므로 변경하지 않음. 실제 쓰기는 별도 운영용 Native writer 경로.
- 기존 경로/파일/링크 충돌 시 실패-차단. 취소되거나 부분 완료되면 생성된 새 폴더는 삭제하지 않고 각각의 실제 결과 표시.
- 실제 생성이 가능한 Windows 로컬 NTFS/ReFS만 지원, NAS/SMB는 미지원.
- 정적 계약 검사, 22개 WPF XML 파싱은 실행했으나 .NET 10 Windows에서의 컴파일·실제 생성·UI DPI 재배치는 **미검증**. 설치 프로그램/업데이트 메타 v1.8.0 공식 안정버전 유지.
- Windows 대상 제한된 검증 스크립트: `validation/R01/RUN_EIASS_R01_WINDOWS.ps1`. 임시 GUID 테스트 폴더만 사용, 설치·배포·GitHub Actions 사용 금지.

## 역사 테스트
- `test_v179_dev*`와 `test_v180_r05_eiass_menu.py` 등의 일부는 *운영용 생성기 금지·2차 읽기 전용 검토창 필수*를 요구하는 구형 계약이다. R01은 사용자 요청에 따라 그 계약을 교체했으므로 구형 테스트 실패를 현재 버전 동적 오류로 오인하지 않는다. 구형 테스트를 삭제하거나 거짓 PASS로 수정하지 않았다.
